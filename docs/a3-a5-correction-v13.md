# A3 / A5 校正 v13（2026-11-06）

默认页面、API 缺省值和 14 个性能表预设重新采用“硬件模型 + 实测校正 / 迁移”。分析值和理想容量模式仍可单独选择。修复了 v10–v12 默认切到解析模式，以及多流、显存预算、EP/TP 改变后校正失效的问题；没有按“实测/仿真必须小于 1”钳制输出。

## A3：固定源配置的效率迁移

保留原始 800T/9392 测点，重新计算“源测量耗时 / 当前源硬件模型耗时 × 目标硬件模型耗时”。源 P 为 DP2 PCP8 TP1 EP16；源 D 为 DP4 TP4 EP16、MTP5。源显存利用率 80%、token 预算 16384 和其他执行假设固定，目标采用 560T、P DP2 PCP8 TP1 EP16、D DP8 TP2 EP16；目标显存 92%、P token 预算 4096/16384 不再影响源测点选择。

源测试未记录多流状态，采用固定开启基线计算校正因子，并明确展示这一假设。目标多流开关只改变目标算子成本。源 batch 超出范围时仅固定效率锚点；目标 batch、输入长度、显存容量和时延继续由目标模型计算。冷/热前缀校正因子连续插值，不覆盖用户请求的命中率。

这是历史测点向 560T 的迁移，不是 560T 本机校准。800T 峰值画像仍是历史代理，不能将迁移误差解释成已验证精度。源数据留出点的时延插值误差：P 冷缓存 −1.36%～+13.94%，P 约90%命中 −22.02%～+10.10%，D −9.37%～+0.18%。这些误差不包含跨硬件、TP4→TP2、目标 batch 外推的不确定性。

## A5：850E 本机测点与 token 预算

850E 保留 96GB 物理容量、91.75GiB 实际可见容量、FP8 KV/indexer。16K token 预算使用 r71 原始训练点重算非负相对加权拟合；独立留出点不参与拟合，P 时延误差 +0.55%～+4.43%，D 周期误差 −8.02%～−5.41%。误差仅适用于记录的输入、batch 和运行条件。

原始 P 测试和新版表均为 eager，但 token 预算和运行配置有差别。新增新版 `vLLM-Ascend 0.32 rc 版本总表.xlsx` 的 `A5 性能总表` 第4行作为 **32K token 预算的汇总校正点**：128K、冷缓存、名义在途数4、TTFT 14.4509s。用该时延除以相同条件的原始模型时延得到倍率，不使用比值列或最优 QPS 反向钳制。源文件 SHA、配置、字段和限制记在 `prefillBudgetReference`。

第5行的90%命中、名义在途数16仅作交叉核对：预测 TTFT 6.0260s，表中6.0470s，相差 −0.347%。该行在修订时已经可见，因此不称盲测或独立验证；缺少逐请求记录、实际缓存 token 和正确性检查，历史 APC 输出不一致的问题也没有据此宣布解决。16K P 第3行存在输出长度/吞吐及并发/TTFT/QPS口径不一致，没有用于拟合。

P 的 batch 表示名义在途请求数，包含调度等待，不等同于内核同时处理的请求数。16K～32K token 预算之间插值校正系数，范围外固定最近系数、继续计算实际预算对应的硬件成本；这是稀疏测点的外推假设，没有新增实机验证。

改变 EP/TP/PCP 时，拟合始终使用原测量拓扑，避免切到 EP16/32 就失去校正。目标拓扑按自己的算子与通信成本计算并标明迁移；EP8 实测权重/物理页内存只用于匹配画像，其他拓扑重算容量。没有 EP16/32 成功实测，本轮也未启动新 NPU 测试。

A5 D 的50ms场景在模型显存边界停止，TPOT约28ms；没有因历史测试只覆盖B1–5而封顶。所有最优值都是受约束的模型预测，不能保证实测一定低于预测。
