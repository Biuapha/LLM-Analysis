# 硬件模型与少量实测校正：最优 batch 搜索

v9 将 A5 850E 的“仅在已测 batch 范围插值”改为硬件建模。A3 560T 的跨硬件预测同样取消训练 batch 上限。实际测试到 B4/B5 或 B32，只说明观测覆盖范围，不定义硬件性能上限。

## 耗时模型

1. 对各算子分别计算计算量、HBM 访问量、batch 相关的占用率、kernel 发射开销，再取算子级 Roofline；显式计入 TP/EP/PCP 通信、MoE 路由、KDA 状态、Indexer 和稀疏注意力。
2. D 的一个 MTP5 周期包含一次 6-token 验证及 5 次串行草稿；覆盖生成过程中的上下文增长。P 计算全部未命中 token 与最后一次 LM head。
3. 850E 同一阶段共用两个校正参数：`T_fit = scale × T_analytic + overhead`。scale、overhead 非负；最小化训练点的相对平方误差，D 按重复次数加权。P/D 分开拟合，16K 与 128K 共同拟合，不为每个输入/batch 单独拟合曲线。验证点不进入拟合。
4. 最终 `T = max(T_ideal, T_fit)`。`T_ideal` 使用相同量化、拓扑、算子和通信预算，满硬件效率、零发射开销，避免校正后快于本模型的硬件理想耗时。
5. 新 batch、新长度、共享/独立前缀及资源参数继续进入解析模型。850E P 在三个本地性能模式下均将 chunk 解释为每 DP 总 token 预算，按 `floor(chunk/batch)` 分给每请求；总量不变，最后不足的 chunk 仍精确计入。原通用模型的每序列 chunk 语义保留并在表单标明。

本次拟合：P scale=2.140477，overhead=244.760 ms；D scale=0.844454，overhead=0。D 的比例小于 1 表示通用解析效率/发射预算偏保守，并不等于超过硬件峰值。理想耗时下界仍逐候选生效。分组耗时只是总耗时校正后的模型预算，不能解释为逐算子实测 trace；P 固定残差也不被归因为已测得的某个算子。

FP8 在模型中影响 KV/indexer 存储与流量；矩阵计算沿用已建模的精度/算力参数，没有凭空填入未核实的 FP8 峰值。850E 目标画像支持 DP8 TP1 EP8 的 D、DP1 PCP8 TP1 EP8 的 P 与 MTP5；改变拓扑、MTP 或显式指定其他精度时，按相应通用模型/迁移路径预测，不宣称匹配这次本机校准。

A3 560T 保留已有 800T 源观测修正：在训练覆盖内使用对应源测点；超过最大 batch 后，固定边界点的“源实测耗时 / 源代理算子耗时”比例，乘以当前目标硬件的算子成本。目标 batch 不再用于索取不存在的源实测，也不会突然退回未校正曲线。该路径同样有理想耗时下界；它仍是迁移预测，不能称为 A3 560T 本机实测。

## 显存与搜索

850E 使用已观测的 91.75 GiB 可见容量、同画像的常驻权重和每物理缓存块成本，重新计算当前容量预算：

`权重 + 请求 KV/MTP 状态 + workspace(batch) + 预留 ≤ 可见容量 × 利用率`

历史预分配 116 个 D 缓存块、6.342 GiB 缓存池以及实测最多同时运行 B4/B5，都保留为观测元数据，**不参与限制最优 batch**。例如预算增大时，模型可分配更多块、继续提高 batch。

当前容量规划复用统一 block-ID 分配模型：完整共享前缀分配一份，私有尾部/状态按请求分配，另计 5 个保护块；独立前缀则逐请求计完整上下文。每块按实际物理成本计费，考虑块边界取整。这个模型代表优化分配下的容量规划，并非逐组重放 r71 混合缓存管理器；图缓存、额外运行时驻留由预留覆盖。实际软件可能需要调整缓存池与调度器才能达到预测并发。因此结果称为“模型显存边界”，不是当前 r71 启动参数的性能保证。

在用户给定扫描范围内逐个评估整数 batch，按显存、TTFT、ITL、TPOT 筛选后取最大 QPS。页面区分时延限制、模型显存限制和用户扫描上限。显存充足时允许固定未测 batch。尚无可用峰值画像的 800T/9392 同机参考入口仍标为实测插值；它与 560T/850E 硬件预测入口分开。

固定 r=3.5 时，`TPOT = 周期 / 3.5`、`QPS = DP × batch / ((输出长度−1) × TPOT)`。输出长度包括 P 产生的第一个 token。r 是用户场景假设，任何训练点都不能覆盖手动 r。选择参考接受产出时，邻近训练点仅提供场景假设；预测仍不会标成实测。

## 独立验证与示例

| 阶段 | 输入 | 验证 batch | 模型时延相对误差 |
|---|---:|---:|---:|
| P | 16K | 3 | +3.690% |
| P | 16K | 6 | +4.791% |
| P | 128K | 3 | +0.432% |
| D 周期 | 16K | 3 | −5.603% |
| D 周期 | 128K | 3 | −8.234% |

这些只验证小 batch 邻域；不能把这些误差当作 B47 等远距离外推的置信区间。16K D B5 只有一次测试，按一次权重纳入训练，拟合低估约 12.88%，保留这一偏差。其他 D 训练点有四次重复。P 的闭环 TTFT 包含调度等待，因此固定开销与比例是整个服务路径的校正，不能视为纯芯片效率。

ITL/TPOT=3.5、输出1024、显存80%、预留4 GiB、D 共享前缀下：

| 硬件/拓扑 | 输入 | TPOT 上限 | 最优 batch/DP | TPOT | QPS | 当前限制 |
|---|---:|---:|---:|---:|---:|---|
| A3 560T DP8 TP2 EP16 | 16K | 50 ms | 72 | 49.776 ms | 11.312 | 时延 |
| A3 560T DP8 TP2 EP16 | 128K | 50 ms | 62 | 49.524 ms | 9.790 | 时延 |
| A3 560T DP8 TP2 EP16 | 128K | 20 ms | 11 | 19.836 ms | 4.337 | 时延 |
| A5 850E DP8 TP1 EP8 | 16K | 20 ms | 44 | 16.975 ms | 20.270 | 模型显存 |
| A5 850E DP8 TP1 EP8 | 128K | 20 ms | 47 | 18.371 ms | 20.007 | 模型显存 |

128K A5 的 B47 预测占 73.248 GiB/rank，预算 73.400 GiB；B48 超出预算。16K 和 128K 的最优 batch 不必单调，因为共享前缀与私有尾部跨越物理块边界，导致每请求块数不同。固定相同 batch 时，长上下文仍增加耗时。

P 的 90% APC 使用未命中 token 的算子模型与冷缓存测点校正，不使用输出一致性检查未通过的 APC 测点；界面继续说明该软件问题。详见[实测记录](a5-850e-calibration-2026-11-05.md)。

复现：运行 `node scripts/report-hardware-calibration.cjs` 查看拟合参数、全部训练/验证误差及上述候选；运行 `node tests/a5-runtime-calibration.test.cjs` 检查未测 batch、显存/SLO、硬件下界、参数响应和验证集隔离。其余五组回归覆盖总表预设、算子与 UI。`python scripts/embed-850e-calibration.py --check` 检查独立页面与可维护源同步。

建模基础：[Berkeley Lab Roofline](https://amcr.lbl.gov/departments/computer-science-department/ppan/roofline-performance-model/)。观测与预测之间的校正、分块调度和显存规划是本仿真系统的建模假设。
