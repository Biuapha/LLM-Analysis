# GLM5.3-Flash / Atlas 850E 实测校准（2026-11-05）

本轮使用实际 8 卡 A5 机器校准。设备报告 Ascend950DT、每卡 96 GiB；机器所有者确认该机器为 Atlas 850E。以下结论属于本次运行环境与负载，不能作为 850E 芯片理论上限或所有软件版本的性能保证。

## 环境与范围

- 镜像：vLLM-Ascend v0.32.0rc，CANN 9.2.1，20261104 r71；镜像 digest、两个代码 commit 见 [校准数据](../data/a5-850e-calibration-20261105.json)。没有修改其他使用者的容器。
- 权重：GLM-5.3-Flash-W8A8-MXFP8-0918，语言模型模式；KV 与 indexer 均为 FP8。旧迁移模型的 int8 KV 假设不等同于这个运行环境。
- D：DP8 TP1 EP8、MTP5、共享前缀、图执行，max-num-seqs=32。
- P：DP1 PCP8 TP1 EP8、MTP5 常驻、eager，max-num-seqs=16。
- 显存利用率 80%，max-model-len=141072，max-num-batched-tokens=16384 **为每 DP 总 token 预算**。
- 自动缓存精度、默认算子倍率、平均时延口径、16K 或 128K 输入才匹配本画像。D 输出固定为 1024。修改精度、拓扑、MTP、显存比例、输入长度或调度配置后，不将这些测点冒充匹配实测。

解析模式的 chunk 参数仍表示每序列分块；实测画像记录运行时总 token 预算。页面现在明确两者的口径。P 的 batch 是固定在途请求数，TTFT 包含调度等待；D 的 batch 是经过指标核实的实际同时解码请求数。

## 纯 D 测量

使用固定重复中文语料、greedy、seed=1024。每个 DP 定向发送相同数量请求，记录流式 token ID、时间、实际命中 token 与 Prometheus MTP 计数。只保留所有请求均已产生首 token 且尚未结束、每个 DP 实际运行数等于目标 batch、等待数为 0、没有抢占的窗口。大并发排队测点不作为大 batch 纯 D 性能。

每个 B1–4 点重复 4 次；B3 留作独立验证，使用 B1/B2/B4 拟合。16K B5 是额外成功的容量边界点，仅 1 次，尚未评估其跨轮波动。每个测点使用 1.5 秒以上有效窗口，并保存窗口内的实际接受计数；原始输出长度仍为 1024，没有换成长输出后宣称测到 1K 输出。

周期由同一稳态窗口的 `TPOT × (1 + accepted_draft_tokens / draft_count)` 推导，不是硬件 ITL trace。固定 r=3.5 时，`TPOT=周期/3.5`、`QPS=DP×batch/(1023×TPOT)`；1024 输出包含 P 产生的首 token。这一列是归一化场景，不是接受率恰为 3.5 的实测吞吐。

B3 独立验证的周期插值误差为：16K −7.91%，128K −7.25%。128K B1/B2/B4 四轮的周期变异系数分别约 0.93% / 0.35% / 0.49%；16K 对应约 1.65% / 0.93% / 0.13%。验证点没有加入训练锚点。

### 容量差异

每卡实际可见容量 91.75 GiB，运行时分到 116 个缓存块，预分配 KV 池约 6.342 GiB，观察到分配器峰值约 65.787 GiB。该混合模型还包含多组 recurrent state 和 MTP 状态，不能仅将完整 prompt 共用一次、再给每请求加一套简单 KV 尾部，就推断运行时可容纳并发。

- 128K 提交 B5 或 B8 时，每 DP 实际最多运行 4 个，其余等待。
- 16K B5 可以形成无等待稳态；提交 B8 时，每 DP 实际最多运行 5 个。
- 自动搜索因此限定为本次已测 B1–4 / B1–5。它不是所有 850E 配置的硬件容量上限；更改运行时内存分配或调度设置需重新测量。

128K、ITL≤70 ms、TPOT≤20 ms、固定 r=3.5 场景，旧 800T 迁移估计选择 B24、QPS=9.538；本次画像选择 B4、归一化 QPS=3.521。两者主要的差异包括运行时实际并发容量、软件与量化配置，不能仅归因于峰值算力。

### 输出一致性边界

128K 冷缓存与热缓存的 8 个 DP 输出各 128 token 完全一致，实际命中 130560 token。

16K 初次冷热检查有差异。进一步进行两次冷缓存、两次热缓存对照，发现冷缓存重复运行本身也不完全确定；两次热缓存与最近一次冷缓存在全部 8 个 DP 上一致，实际命中 8704 token。因此没有据初次差异直接认定 APC 错误，也没有删除不利记录。此检查只约束本次合成负载，不能替代模型精度评测。

## 纯 P 测量

使用可复现的合成 token ID 输入、1 token 输出。每个并发点先进行两轮预热，再等待闭环负载稳定 15 秒，测量 90 秒；无缓存命中测点每个请求使用不同输入，并逐请求确认实际命中为 0。客户端保持固定在途数，不将排队请求冒充同时执行的 batch。

| 输入 | 每 DP 在途数 | 平均 TTFT | 90 秒完成请求数 | 窗口 QPS | 用途 |
|---|---:|---:|---:|---:|---|
| 16K | 1 | 0.836 s | 107 | 1.189 | 训练 |
| 16K | 2 | 1.610 s | 111 | 1.233 | 训练，原验证点 |
| 16K | 3 | 2.073 s | 130 | 1.444 | 验证 |
| 16K | 4 | 2.542 s | 141 | 1.567 | 训练 |
| 16K | 6 | 3.821 s | 141 | 1.567 | 验证 |
| 16K | 8 | 5.095 s | 141 | 1.567 | 训练 |
| 128K | 1 | 5.659 s | 16 | 0.178 | 训练 |
| 128K | 2 | 10.200 s | 18 | 0.200 | 训练 |
| 128K | 3 | 15.484 s | 18 | 0.200 | 验证 |
| 128K | 4 | 20.430 s | 18 | 0.200 | 训练 |

最初 B1/B4/B8 插值对 16K B2 低估约 12.8%；在读取后续 B3/B6 结果前，将 B2 加入训练锚点。最终仍独立保留 B3/B6：16K 插值误差为 +0.129% / −0.062%，128K B3 为 −1.094%。本次 P 每点只有一个 90 秒窗口，误差不能代表跨轮或真实业务负载的分布。

TTFT≤2 秒时，16K 选择每 DP 在途数 2，仿真 QPS=`2/1.610491=1.242`；TTFT≤15 秒时，128K 选择在途数 2，QPS=`2/10.200064=0.196`。页面使用闭环关系 `QPS=DP×在途数/TTFT`，表中窗口完成计数受有限窗口和客户端周转影响，两种口径分别保存，没有将它们混为同一个实测数字。128K 在途数 3 的实测与插值均超过 15 秒。

P 启动日志权重为 43.22 GiB/rank，缓存池约 14.377 GiB/rank、1966 个块，物理主块长 1152。D 的权重常驻量、缓存分组和块长不同；接入时分别记录，没有套用 D 的显存几何。

### PCP8 前缀缓存检查未通过

128K、请求 90% 前缀复用时，实际命中 117504 token（89.6484%）。使用相同完整输入，重置缓存后直接计算与“先计算共享前缀，再补齐后缀”的结果不同：初次检查后追加两次冷缓存、两次热缓存对照，两次冷运行均返回首 token **4793**，两次热运行均返回 **98314**。

这是一条可重复的冷热输出差异，根因尚未定位，不能仅凭 token 不同就断言具体算子错误或衡量精度下降幅度。该 90% APC 场景没有进入吞吐校准，也没有生成性能训练锚点。页面保留原估算路径，但明确显示“未通过本轮输出校验”，不能把其性能数字当作本次通过验证的实测结果。

## 仿真接入与复现

同配置优先使用本机测点，超出已测 batch 不外推；其他参数组合保留原估算路径并显示来源。手动 r 不会被实测接受率覆盖，选择“同配置参考”才使用测得的接受产出。没有逐算子 trace，因此此画像不展示伪造的逐算子耗时分解，也不支持末端时延或 p99 校准。
