# GLM5.3-flash 表格实测 / 仿真比值审计

## 发现与修正

`vLLM-Ascend 0.32 rc 版本总表 (1).xlsx` 的 `A5 性能总表!AT3` 为
`AR3/BH3`：实测 QPS 4.3783 / 原解析估计 3.5793223928766027 = 1.2232203527442749。
公式和单位一致，不能用截断比值或抬高分母来消除偏差。

PCP 通信路径原先给每个 KDA 层计了两次完整序列输出 all-reduce。
KDA 实际仅有一次 `o_proj` row-parallel reduction；另一条 FFN reduction
属于 TP 通信。现在只替换 KDA attention 的那一次 reduction，保留 FFN 的 TP 路径。
TP1 时不再凭空增加第二次 PCP reduction；TP>1 时也不再把 FFN 的本地 token
归约误按完整序列计费。输入 gather 和 SFA 通信继续计入。

依据为 [vLLM Ascend KDA 源码](https://github.com/vllm-project/vllm-ascend/blob/0f2eee9dfc5b4567c83752abb6b81ae302f83a05/vllm_ascend/models/glm5next/kda.py)
的 `PCPRowParallelLinear.forward`、KDA `o_proj`、输入 `all_gather` 和输出切片。
另以已安装 r71 镜像源码核对了同一流程，无需启动 NPU 作业。

先前表格生成过程统一设置 `chunk=16384, util=80`，没有对齐 M 列的
`kv_producer` 启动命令。本次纯 P 分别读取生产端参数：

| 表格行 | 每 DP token 预算 | 显存利用率 |
| --- | ---: | ---: |
| A3 3–4 | 4096 | 92% |
| A3 5 | 16384 | 92% |
| A5 3–5 | 32768 | 90% |

网页的表格场景载入器同时恢复每行的分块预算、显存利用率、预留和搜索上限，
使选择场景后从真实表单执行的结果与表内预设一致。

保留指定拓扑：A3 P DP2 PCP8 TP1 EP16；A5 P DP1 PCP8 TP1 EP8。
纯 P 搜索上限扩展到 256，最终六个最优点均未触及扫描上限。
MTP5、ITL/TPOT=3.5、每 rank 预留 4 GiB 和原 TTFT 约束保持不变。
纯 D 的 80% 显存预算、拓扑和全部数值保持原配置，不由纯 P 的命令覆盖。
原始实测记录可能使用不同 MTP 草稿数或实际接受率，不能声称所有实测配置与该固定仿真场景完全相同。

A5 第 3 行实测仍高于解析估计 5.29%；该差距尚未被解释或校准。
`analytic` 是具有参考效率、算子和通信近似的性能预测，并非数学上保证的硬件吞吐上限。
本次没有引入面向该行的时延倍率，也没有切换成 `ideal` 来改变比值。
工作簿来源单元格明确标注“解析估计，非上限”，并保留这个超过 1 的数值。
MiniMax 的 AT56、AT58 也大于 1，但未在本次仅限 GLM 的修改范围内。
