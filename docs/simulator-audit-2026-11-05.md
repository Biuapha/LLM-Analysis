# 仿真系统计算与交互审计（2026-11-05）

本轮在 `882f407` 的 Indexer 修正基础上检查 GLM / DeepSeek 两套计算内核、显存、并行拓扑、校准覆盖、搜索、页面展示和导出。以下为已复现并修正的问题；没有以期望的硬件性能比例反调参数。

## 已修复问题

| 类别 | 原问题及影响 | 修正 |
|---|---|---|
| 1. Decode token 计数 | GLM MTP0 和 DeepSeek 按 O 步计费，GLM MTP 按 O−1；页面和 JSON 定义也不一致。 | 统一 O 包含 P 产生的首 token，D 耗时为 `(O−1) × 平均 TPOT`；同步上下文、步骤、显示公式及导出定义。 |
| 2. 无 D 工作的边界 | O=1 仍产生正的 D QPS，甚至显示可选 batch。 | 返回 `notApplicable`、空候选、无最优 batch；页面明确“无需 Decode”。原生适配器尚不支持跳过 D，提交前提示使用本地内核。 |
| 3. 短输出草稿 | GLM 在 O=2 仍验证两个位置；DeepSeek 固定验证 6 个位置、草稿 5 个位置。 | 验证位置、草稿位置、接受产出不超过剩余 D token；O=2 只执行一次目标前向，没有草稿开销。仍保留配置所需常驻草稿权重/缓存预留。 |
| 4. MTP0 共享前缀 | 选择共享前缀后，MTP0 仍逐请求复制整个 prompt，低估显存可容纳 batch。 | MTP0/MTP 共用块分配逻辑，只共享完整前缀块，私有解码块和保护块独立计费。命中率本身不自动带来共享折扣。 |
| 5. KV 精度一致性 | 在迁移范围外的固定 batch 回退路径中，显存按 int8、算子访问按 BF16 计费。 | 算子使用显存模型的有效 KV dtype；显式 BF16 不套用 int8 迁移，800T 未覆盖精度直接报告无匹配实测。 |
| 6. KPool 与尾部 | 用 ceil 计入尚未完成的池，TopK 后遗漏 0–3 个未池化 token；极短输入的求和没有单独切开尾状态增长边界。 | 按 `floor(context/4)` 计完整池，另计因果尾部；补充积分切分。用参考选择规则逐位置对照，覆盖 4、2048 边界。 |
| 7. 专家 TP workspace | EP=1 时 FFN 临时中间量没有除 expertTP，而对应计算/激活已分片，显存被高估。 | 临时中间量按相同 expertTP 切分；验证多机 TP/EP 组合。 |
| 8. 时延显示 | 平均模式卡片使用平均值，候选表、曲线提示和部分标签却使用末端值；缺失 ITL 会显示为 0。 | 所有展示遵循所选统计口径，缺失时延显示“—”；无可行候选的提示也显示对应统计值。最优 batch 标签明确“每 DP”。 |
| 9. 校准证据边界 | 未核实机型的历史记录被显示为 752T 同配置实测偏差；800T 实测静默覆盖用户手动 r。 | 历史记录保留，但不作为已确认 SKU 的验证证据；800T 要求选择同配置实测产出。无匹配参考时明确回到 r=1。 |
| 10. 无效参数 | JSON 克隆把 NaN 变为 null，固定 batch 的 `||0` 又使其变成自动搜索；部分无效选项被默认为其他含义。 | 保留无效数值交由验证，检查统计/布局/精度和手动产出范围。DeepSeek 缺少资源配置或选择无解析画像硬件时返回错误，避免抛异常或计算非有限值。 |
| 11. 原生模式 | 新保存的任务被旧版恢复条件拒绝；ITL 控件可能禁用但仍参与双约束；800T 校验发生在提交后。 | 恢复兼容当前 MTP0/r=1 任务；双约束控件与有效参数一致，切回本地恢复原设置；不支持的画像在提交前拒绝。 |
| 12. 搜索提示 | 扫描上限低于数据覆盖下限时，提示硬编码为 MTP5/B4–8，可能与实际范围不符。 | 提示真实的覆盖下限与扫描上限。 |

KPool 选择规则依据已检查的 vLLM Ascend 参考测试：

## 尚需实机验证的模型假设

- 这些检查确认实现的一致性，不能证明所有算子模型或硬件预测都准确。A3/A5 比较仍是 800T 锚点迁移，未经目标机器的同配置实测验证。
- MTP/DSpark 使用平均产出的流体容量估计和三点上下文积分，没有模拟有限请求的末轮接受/拒绝分布、队列、动态合批、抢占及 p99。短输出已限制计算位置，但仍不是逐次随机生成仿真。
- 共享前缀意味着相同 prompt 的完整缓存块可共享；独立真实业务前缀应选择独立布局。分配器预留、图缓存和碎片仍需实测。
- 算子占用率、融合、通信拓扑和专家负载使用现有规划假设。DeepSeek 的 DSpark 接受产出仍由所填 ITL/TPOT 目标构造，页面明确标为场景假设，并非预测的接受率。
- 原生适配器的预检、参数和恢复路径经过模拟服务验证；本轮没有运行外部 msmodeling 后端。

`tokensPerSecond` 保持响应输出吞吐口径（QPS×O，包含首 token），不是纯 D 实际计算 token 数；D 服务时长和 QPS 分母统一使用 O−1。之前导出的 Excel 未在本轮改写。
