# Atlas 850 / 850E 纯 P 效率口径统一（2026-11-09）

v13 在“硬件模型 + 实测校正”模式中，850 使用未经实测校正的算子耗时，850E 使用本机冷缓存测点拟合的服务耗时。128K、95% 命中时，这种不对称校正会让 850 的预测 QPS 高于 850E，不能解释为已经验证的硬件差距。

v14 将同一组 850E **纯 P** 效率参数迁移到 850：

`T_target = max(T_target_ideal, source_scale × T_target_analytic + source_overhead)`

拟合仍只读取原有 850E 冷缓存训练点及 32K token 预算的冷缓存汇总点；没有新增或修改测量数据。16K 预算的 scale=2.4423984692、overhead=0.2476125049 秒；32K 预算的 scale=1.8068127648、overhead=0。中间预算延用原插值规则。源拟合固定原拓扑和效率，目标带宽、并行布局、多流和容量改变不重新拟合源测点。

850 目标模型继续使用自身 1.4 TB/s 带宽、112 GiB 容量、目标拓扑及默认 INT8 KV/indexer；显式 FP8 也支持迁移。850E 使用原 4 TiB/s、FP8 和匹配拓扑的运行时内存记录。不会将 850E 的 91.75 GiB 可见容量、已载入权重或物理页成本套到 850。两者共用每 DP 总 token 预算，仍逐候选执行显存、TTFT 和理想硬件耗时下界检查。

范围沿用 MTP5 画像；850 的 BF16 KV 或其他 MTP 设置保留原算子估计。850E 现有适用范围、A3、两类 A5 的 Decode 路径、第 5 页 B28 六曲线及 QPS 标记保持原结果。解析模式、理想模式仍可单独查看。

## 128K、95% 命中复算

每请求命中 124518 tokens，实算 6554 tokens。以下均为单机 8 卡、DP1 / TP1 / PCP8 / EP8、80% 显存利用率、4 GiB 预留、多流开启、整机请求 QPS。

| 每 DP token 预算 | 每 DP 在途 batch | 850 原 QPS | 850 v14 QPS | 850E QPS（不变） |
|---|---:|---:|---:|---:|
| 16384 | 4 | 6.8001 | 2.3749 | 3.0216 |
| 32768 | 4 | 7.2869 | 4.0330 | 5.2671 |

TTFT≤7 秒、batch 扫描 1–256 时，16K 预算的 850 最优 B17 / QPS 2.7201，850E 最优 B22 / QPS 3.5765；32K 预算两者最优 B19，QPS 分别 4.0577 / 5.3063。

剩余差异来自目标算子模型的带宽等成本及约束下的 batch 选择。固定相同 batch、KV 精度及带宽后，两者的预测服务耗时相同；未按指定 QPS 或差距反向调参。

## 证据边界与验证

850 的结果标为“850E 实测效率迁移”，`targetEmpiricallyValidated=false`，没有 850 本机纯 P 测点。目标实测覆盖字段为空，源测点覆盖另列。95% 等缓存命中场景沿用冷缓存效率，属于外推；这次更新没有证明高命中场景的准确性，也没有解决原 850E PCP8 APC 输出一致性记录中的问题。分组耗时仍是模型预算，不是实测算子归因。

`node tests/a5-prefill-transfer.test.cjs` 检查跨硬件效率迁移、等硬件耗时一致、源拟合隔离、目标精度/容量、缓存 token、SLO 搜索，以及页面和导出中的来源说明。既有校准验证集与 A3/Decode/六曲线回归继续执行；未读取图片。
