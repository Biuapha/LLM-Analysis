三组曲线同源权重 · MXFP8-0918

使用 GLM-5.3-Flash-W8A8-MXFP8-0918 的实际 safetensors header 重算。原始 checkpoint 共 76,108 个 tensor，包含视觉的文件载荷为 338,074,909,560 B；不是 NPU 实测驻留。

网页计算完整 45 个主模型层 + 1 个 MTP 层。曲线实验使用 L4 / L7 / L45 → L0 / L1 / L2 的缩层模型。按同样规则生成的 config 与量化描述 SHA256，和当时曲线运行记录完全一致；缩层载荷 25,695,681,840 B、5,284 个 tensor 也吻合。不要把缩层模型加载显存直接当成完整模型显存。

矩阵形状为 [N,K] 时，权重载荷为 N × K B + N × (K / 32) B。本 checkpoint 的相关 K 均整除 32。第二项是 block scale；不能套用 INT8 的逐输出通道 FP32 scale / offset 公式。

TP、EP 与共享权重

EP 开启时，一个 rank 持有分配到的完整专家，不再除 TP；EP 关闭时专家按 DP×TP 切中间维。MXFP8 的 down projection scale 同样随 K 维切分。Dense / Shared MLP 按所选 SP 复制或 TP 切分。非整除 EP 使用最多专家的 rank 做容量规划，并显示最小 rank 的权重。

该 checkpoint 没有独立的 MTP Embedding / LM Head；运行时 MTP 共享目标模型的 Embedding，且 has_own_lm_head=False 使用目标 LM Head。全局只计一份 Embedding 和一份 LM Head；这两者本身仍是独立权重。q=0 关闭 MTP 时，这两份全局权重仍需保留。

计算边界

默认关闭视觉，与曲线的 --language-model-only 一致。DP / TP / EP、显存容量和预留仍可自行设置；曲线实际是 DP8 / TP1 / EP8。已知 FP32 转换和常驻副本可勾选计入，NZ 打包、scale 成对 padding、vocab padding、临时缓冲、激活和 workspace 仍由预留覆盖。4 GiB 是可调整的预算，不是此次实测值。

本次对齐的是权重。第三页的 KV 分配继续使用原 BF16 / FP32 预算布局；曲线实际使用 FP8 KV / Indexer，因此该 KV 结果不是曲线运行的实测值。第四页性能仿真保留独立的历史校准口径。
